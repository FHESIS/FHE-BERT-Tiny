# Plaintext Implementation — Optimization Results

Implements the changes proposed in `PLAINTEXT_OPTIMIZATION_REPORT.md` and
compares the optimized plaintext circuit against the pre-optimization
baseline, on deviation, latency, and total runtime.

## What changed (`src/python/PlainCircuit.py`)

Applied incrementally, verifying logits after each step before moving to the next:

1. **`HF_HUB_OFFLINE=1` default** — skips the Hugging Face Hub etag
   round-trip for the (already locally cached) tokenizer.
2. **Removed dead code** — an unused `tokenizer(text)` call.
3. **Vectorized the four LayerNorm applications** — replaced per-token
   Python `for` loops (with a `torch.cat` rebuild and repeated
   `model...LayerNorm.weight` attribute lookups each iteration) with a
   single broadcasted tensor expression per LayerNorm, matching the
   approach already prototyped in `PlainCircuitSimplified.py`.
4. **Extracted `load_model()` / `classify()` functions** (`@torch.no_grad()`
   on the latter) so the tokenizer/model can be loaded once and reused
   across many sentences in one process, instead of one subprocess (and one
   `import transformers`/model reload) per sentence. The CLI (`python3
   PlainCircuit.py "<sentence>"`) is unchanged for a single sentence;
   passing multiple sentences as separate argv now classifies all of them
   against the one loaded model.

New file: `src/python/run_plaintext_benchmark_v2.py` — loads the model once
and benchmarks all 100 sentences from `run_sentiment_comparison.py`'s
`SENTENCES` list in a single process, timing each `classify()` call
individually. Raw output: `plaintext_optimized_results.json`.

## Baseline

`sentiment_comparison_results.json`, generated by the unmodified,
pre-optimization `PlainCircuit.py` via `run_sentiment_comparison.py`
(subprocess-per-sentence), **50 sentences** (all `positive`-labeled — the
first 50 of the 100-sentence set; the run was interrupted before the
remaining 50). Same machine, same model weights, same transformers version.

## Correctness: deviation from baseline

The optimized circuit was run on the exact same 50 sentences plus the
remaining 50 (100 total). Comparing logits pairwise on the 50 sentences
present in both:

| Metric | Value |
|---|---|
| Sentences compared | 50/50 |
| Max \|Δlogit₀\| | 4.98 × 10⁻⁹ |
| Max \|Δlogit₁\| | 4.98 × 10⁻⁹ |
| Mean \|Δlogit\| | 2.62 × 10⁻⁹ |
| Predicted-sentiment mismatches | **0 / 50** |
| Accuracy vs. expected label, same 50 sentences | 39/50 — identical to baseline |

The residual ~5×10⁻⁹ difference (logit magnitudes are ~1–3) is ordinary
floating-point reordering noise from batching the four LayerNorm ops into
one tensor expression instead of a per-token Python loop (same math,
elementwise, no summation — not something either version "gets more right,"
just different instruction ordering). It's roughly 9 orders of magnitude
below the logit scale and never flips a prediction. Also cross-checked
against the older, independent 4-sentence baseline in `benchmark_results.json`
(includes 2 negative-labeled sentences not in the 50 above): same result,
max diff 4.6×10⁻⁹, 4/4 predictions unchanged.

Verdict: **numerically equivalent to the pre-optimization implementation.**

## Latency

| | Baseline (subprocess/sentence) | Optimized (classify() only, model preloaded) |
|---|---|---|
| N | 50 | 100 (99 steady-state, excl. 1st-call GPU warm-up) |
| Mean | 10.566 s | 9.92 ms |
| Median | 10.485 s | 9.60 ms |
| Min | 10.328 s | 9.60 ms |
| Max | 11.053 s | 35.40 ms |

The baseline's "latency" is ~99% fixed process-startup cost (import +
model/tokenizer load) repeated every call, as established in
`PLAINTEXT_OPTIMIZATION_REPORT.md`; the optimized number isolates the part
that actually scales with the sentence — a **~1065x** reduction in
per-additional-sentence cost. The first `classify()` call after model load
took 461 ms (one-time CUDA kernel warm-up, not present in the baseline since
it ran on CPU-timed subprocess boundaries); every call after that is
9.6–35 ms.

## Total runtime

| | Baseline | Optimized |
|---|---|---|
| Sentences | 50 | 100 |
| Model/tokenizer load | paid 50× (bundled into each subprocess) | paid once: 0.615 s |
| Total wall-clock | 528.301 s | 10.370 s (measured with `time`, includes Python/library import) |
| Effective throughput | 1 sentence / 10.57 s | 1 sentence / 0.104 s (100-sentence run) |

For a like-for-like sentence count, the optimized run's first 50 sentences
(including the one-time load + import) finish in **≈10.0 s** versus the
baseline's **528.3 s** for the same 50 — a **≈53x** speedup; run the full
100-sentence set and it's **≈102x** (528.3 s → 10.37 s for the equivalent
scaled baseline of ~1056.6 s), since the fixed ~9.3 s of import+load
amortizes further the more sentences are classified in one process. A
1000-sentence batch would be projected at ~9.3 s + 1000×0.0099 s ≈ **19 s**
versus baseline's ~10,566 s (**≈550x**).

## Net effect

- **Correctness:** unchanged (0 prediction mismatches, ~5×10⁻⁹ logit noise).
- **Latency per sentence (steady state):** 10.57 s → 9.9 ms.
- **Total runtime, 50-sentence benchmark:** 528.3 s → ~10.0 s (≈53x).
- **Total runtime, 100-sentence benchmark:** ~1056.6 s (projected) → 10.37 s (≈102x).

## Not changed

`ServerCircuit.cpp` (encrypted circuit) is untouched — none of these
optimizations apply there; its performance was addressed separately in
`PERFORMANCE_REPORT.md`. `run_sentiment_comparison.py` / `run_benchmark.py`
still use the old subprocess-per-sentence path for plaintext by default
(kept for backward compatibility and because they interleave
plaintext/encrypted runs); `run_plaintext_benchmark_v2.py` is the new
plaintext-only, in-process runner used for this comparison.
